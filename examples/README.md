# Example bundle

`sample-bundle/` is a **synthetic, already-redacted** support bundle, laid out
exactly as `mistral-furball.sh` produces it. Nothing here came from a
real cluster — node/pod names are anonymized-style tokens, IPs appear as `<ip>`,
and no secrets or inference payloads are present. Use it to see the shape of the
output before running the tool.

```
sample-bundle/mistral-furball-prod-gpu-20260812T101500Z/
├── SUMMARY.txt            # at-a-glance findings (generated by write_summary)
├── README-INSIDE.txt      # what is / isn't in the bundle (generated)
├── manifest.json          # machine-readable run record
├── redaction-summary.txt  # per-file count of scrubbed values
├── cluster/               # versions, nodes, storage classes, distro hint
├── gpu/                   # GPU node capacity, nvidia-smi
├── workload/              # serving spec, images, engine args
├── state/                 # pod status, red-flag scan
├── logs/                  # bounded container logs
└── metrics/               # kubectl top output
```

`SUMMARY.txt`, `README-INSIDE.txt`, and `manifest.json` are the real generator
output for this synthetic tree. The scenario is a healthy 3-node cluster (2 GPU
nodes, 8x H100 each) serving `mistral-inference-engine` with no anomalies — a
"nominal" bundle a support engineer can use as a baseline.

Start with `SUMMARY.txt`.
